## BeanStalk

- Equivalent to "Azure App Service"
- Another Compute Service
- Fully Managed Runtime Platform (PaaS)
- Offers Autoscaling feature
- We are only responsible for data and application code.
- It is a Zonal Service, All the EC2 instances run in a single Availability Zone.

  ![alt text](images/{5BB11E86-46B4-4BFD-AEFB-201634CE8243}.png)

## BeanStalk Components

- **Application** :
  - Each deployment creates a new Application Version
  - The application code is stored in S3 bucket
- **Environment** :
  - The resouces running the code like collection of EC2 instances (Auto Scaling Group), fully managed by AWS for us.
- **Platform** :
  - Combination of OS + Runtime, that runs the code.
  - Linux + Dotnet Core
- **Tier** :
  - Defines the type of application
    - Web Server
      - For Web Application
    - Worker
      - For Batch Processing

| Deployment Strategy               | AWS Elastic Beanstalk                                                        | Azure App Service                                  | Notes                                                                                                                                                      |
| --------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **All at Once**                   | ✅ Native                                                                    | ❌ Not a named deployment option                   | Azure deploys to the app/slot directly; no explicit "all at once" policy.                                                                                  |
| **Rolling**                       | ✅ Native                                                                    | ❌ Not exposed as a deployment strategy            | Azure manages infrastructure updates automatically but doesn't offer user-configurable rolling deployments for app releases.                               |
| **Rolling with Additional Batch** | ✅ Native                                                                    | ❌ No                                              | Azure App Service doesn't let you configure batch-based instance updates.                                                                                  |
| **Immutable**                     | ✅ Native                                                                    | ❌ No direct equivalent                            | Closest Azure approach is deploying to a new deployment slot, but it doesn't create a separate infrastructure stack like Beanstalk's immutable deployment. |
| **Blue/Green**                    | ✅ Native (separate environments)                                            | ✅ Using Deployment Slots                          | Azure deployment slot swap provides near-zero downtime.                                                                                                    |
| **Canary**                        | ❌ Not native (requires additional services such as CodeDeploy/ALB/Route 53) | ✅ Supported using deployment slot traffic routing | Azure can gradually route a percentage of traffic (e.g., 5%, 10%, 50%) to a staging slot before a full swap.                                               |
