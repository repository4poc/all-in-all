## Disk Type

Disk type affects the Reliablity (SLA), Performance and Cost of Virtual Machine

**Disk Types**

- Instance Store
- EBS

| AWS                                  | Azure Equivalent                    | Description                                                                                                                                                                      |
| ------------------------------------ | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instance Store**                   | **Temporary Disk (Local SSD/NVMe)** | Physically attached to the host machine. Very fast, but data is lost if the VM is stopped, deallocated, or moved to another host. Used for cache, temp files, and scratch space. |
| **Amazon EBS (Elastic Block Store)** | **Azure Managed Disks**             | Persistent block storage that remains even if the VM is stopped or restarted. Can be detached and attached to another VM. Used for OS and data disks.                            |

| Feature                  | AWS Instance Store | Azure Temporary Disk | AWS EBS                          | Azure Managed Disks              |
| ------------------------ | ------------------ | -------------------- | -------------------------------- | -------------------------------- |
| Persistent               | ❌ No              | ❌ No                | ✅ Yes                           | ✅ Yes                           |
| Attached to VM           | Local              | Local                | Network-attached                 | Network-attached                 |
| Survives VM reboot       | Usually Yes        | Usually Yes          | Yes                              | Yes                              |
| Survives VM deallocation | ❌ No              | ❌ No                | ✅ Yes                           | ✅ Yes                           |
| Best for                 | Cache, temp data   | Cache, temp data     | OS disk, databases, applications | OS disk, databases, applications |

## EFS (Elastic File System)

- Managed Network File/Shared Storage, can be attached to multiple VMs at a time.
- Azure equivalent : Azure File Share
- Offer Autoscaling and Reliable
  - Durability : 99.999999999%
  - SLA : 99.99%
- Can be attached to EC2, ECS, Lambda, EKS more
- Can be Zonal and Regional

| Feature                              | AWS EFS                                          | Azure Files                                                                                  |
| ------------------------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| **Regional**                         | ✅ Regional EFS (recommended)                    | ✅ Regional (default)                                                                        |
| **Single Availability Zone (Zonal)** | ✅ One Zone EFS                                  | ❌ No direct "Zonal File Share" option                                                       |
| **Multi-AZ Availability**            | Regional EFS replicates across AZs automatically | Achieved through storage account redundancy (ZRS or GZRS), not by creating zonal file shares |

| Feature                    | AWS EFS                                     | Azure Files                                                         |
| -------------------------- | ------------------------------------------- | ------------------------------------------------------------------- |
| Storage Type               | Managed File Storage                        | Managed File Storage                                                |
| Protocols                  | NFS (v4.x)                                  | SMB, NFS                                                            |
| Shared Across Multiple VMs | ✅                                          | ✅                                                                  |
| Fully Managed              | ✅                                          | ✅                                                                  |
| Auto Scaling               | ✅                                          | ✅                                                                  |
| Typical Use Cases          | Linux shared storage, web farms, containers | Windows/Linux shared storage, lift-and-shift, Azure Virtual Desktop |

## Auto Scaling Group

- A collection of EC2 instances managed as a single Entity.
- Great for systems, require more than single instance.
- Offers VM Autoscaling capability to handle changing load
- The instances can be distributed across Availability Zones
- Equivalent to Azure Virtual Machine Scale Set

**ASG Features**

![alt text](images/ASGFeatures.png)

| Feature                   | **AWS Auto Scaling Group (ASG)**       | **Azure Virtual Machine Scale Set (VMSS)**         |
| ------------------------- | -------------------------------------- | -------------------------------------------------- |
| Purpose                   | Automatically scale EC2 instances      | Automatically scale Azure VMs                      |
| VM Template               | Uses **Launch Template**               | VM configuration built into VMSS                   |
| Scaling                   | Manual, scheduled, dynamic, predictive | Manual, scheduled, metric-based                    |
| Load Balancer Integration | Elastic Load Balancer (ALB/NLB)        | Azure Load Balancer / Application Gateway          |

| **AWS Placement Group**       | **Purpose**                                                              | **Azure Equivalent**                                                                       |
| ----------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **Cluster Placement Group**   | Place VMs close together for low latency                                 | **Proximity Placement Group (PPG)**                                                        |
| **Spread Placement Group**    | Spread instances across different hardware to reduce correlated failures | **Availability Zone** or **Availability Set**                                              |
| **Partition Placement Group** | Place instances into isolated partitions (racks)                         | **Virtual Machine Scale Set (Fault Domains)** or **Availability Set** (closest equivalent) |

The closest Azure equivalent to AWS Systems Manager (SSM) is not a single service, but a combination of Azure services

| AWS Systems Manager feature    | Azure equivalent                           |
| ------------------------------ | ------------------------------------------ |
| Fleet management               | Azure Arc                                  |
| Run Command                    | Azure VM Run Command or Azure Automation   |
| State Manager (configuration)  | Azure Automation State Configuration       |
| Patch Manager                  | Azure Update Manager                       |
| Session Manager (shell access) | Azure Bastion or SSH/RDP via Bastion       |
| Parameter Store                | Azure App Configuration or Azure Key Vault |
| Inventory                      | Azure Arc + Azure Monitor                  |
| Automation documents           | Azure Automation (Runbooks)                |
