## CloudFormation

![alt text](images/{6030C17C-1D0E-469E-92A8-373954C776D7}.png)

| AWS                                  | Azure                                               | Purpose                                       |
| ------------------------------------ | --------------------------------------------------- | --------------------------------------------- |
| AWS CloudFormation                   | Azure Resource Manager                              | Deploy and manage infrastructure as code      |
| CloudFormation Templates (JSON/YAML) | ARM Templates (JSON)                                | Declarative infrastructure definitions        |
| AWS Cloud Development Kit            | Azure Bicep                                         | Simpler syntax that compiles to ARM templates |
| CloudFormation Stack                 | Resource Group Deployment / Subscription Deployment | Logical deployment unit                       |
| Stack Update                         | Incremental or Complete Deployment                  | Update existing infrastructure                |
| Stack Drift Detection                | What-if Deployment + Resource Graph + Policy        | Preview and detect configuration differences  |

## AWS CDK Constrcts

There are 3 level of CDK constructs

- L1 Level Constructs : Cfn (Cloud Formation) Resources, when used, we must configure all properties
- L2 Level Constructs : Mostly Used, Provide typesafety and abstraction
- L3 Level Constructs : Called Patterns, combile multiple AWS resources, like LambdaRestAPI

## CDK ID

Resource Logical ID for resource.

![alt text](images/{31F77B47-A80B-4F4B-B2F2-A521B1826C41}.png)
![alt text](images/{331BFE76-FAA5-4CC2-AE95-C2C6034607A9}.png)

- Logical/Construct ID : CDK resource ID (For refering resource within CDK)
- Physical ID : AWS resource ID (For refering resource within AWS)

If we change the Logical/Construct ID, CDK will

- Try to create a new resource
- Delete the old one.
  But as the AWS resouce within the construct already exists, so it will fail in first step. so we have to delete the AWS resource manually.

## **cdk-nag**

cdk-nag is a security/compliance checking tool for AWS CDK apps.

It scans your CDK infrastructure code and warns you when resources do not follow best practices, for example:

- S3 bucket without encryption
- S3 bucket without access logging
- IAM policy using \*
- Security group open to the world
- CloudWatch logging not enabled

It works by using CDK Aspects to inspect every resource in your CDK stack during `cdk synth`.

Example use in TypeScript:
![alt text](images/{E4A86487-BBB1-4B43-B3C3-3CE81CEE125D}.png)

```
#!/usr/bin/env node
import * as cdk from "aws-cdk-lib";
import { InfraProjectStack } from "../lib/infra_project-stack";
import { AwsSolutionsChecks } from "cdk-nag";
import { App, Validations } from "aws-cdk-lib";

const app = new cdk.App();

// Create an instance of the InfraProjectStack and specify the AWS account and region
new InfraProjectStack(app, "InfraProjectStack", {
  env: { account: "127112147701", region: "eu-north-1" },
});


Validations.of(app).addPlugins(new AwsSolutionsChecks(app, { verbose: true }));


```

```
cdk synth
```

If something is wrong, cdk-nag shows findings like:

```
AwsSolutions-S1: S3 Bucket should have server access logging enabled.

AwsSolutions-IAM5: IAM policy should not allow wildcard permissions.
```
